# Deploy — Render + MongoDB Atlas

Live setup: React static site + Express API on [Render](https://render.com),
database on [MongoDB Atlas](https://www.mongodb.com/atlas) (free M0).

```
Browser ──▶ bookflow-client (Render static, React)
   │
   │  XHR to VITE_API_BASE (the API origin, baked in at build)
   ▼
bookflow-server (Render web, Docker) ──▶ MongoDB Atlas
   ▲
   └── Stripe webhook  (checkout.session.completed)
```

## 1. MongoDB Atlas

1. Create a free **M0** cluster.
2. **Database Access** → add a user (username + password).
3. **Network Access** → add `0.0.0.0/0` (Render IPs are dynamic on free plan).
4. **Connect → Drivers** → copy the SRV string, e.g.
   `mongodb+srv://USER:PASS@cluster0.xxxx.mongodb.net/booking?retryWrites=true&w=majority`
   (add the `/booking` database name before the `?`).

## 2. Render Blueprint

1. Push this branch to GitHub (already done) and open a PR / merge to `main`.
2. Render Dashboard → **New → Blueprint** → pick this repo → it reads
   [`render.yaml`](render.yaml) and creates **bookflow-server** + **bookflow-client**.
3. When prompted, set the server's secret env vars:
   | key | value |
   |---|---|
   | `MONGO_URI` | the Atlas SRV string from step 1 |
   | `STRIPE_SECRET_KEY` | `sk_test_...` (or `sk_live_...`) |
   | `STRIPE_WEBHOOK_SECRET` | fill in step 3, redeploy after |

   `JWT_SECRET` is generated by Render automatically. `CLIENT_HOST` (server) and
   `API_HOST` (client build) are wired from each other's service host in
   `render.yaml` — no service-name string is hardcoded, so renaming a service
   just triggers a rebuild.
4. First deploy runs. `bookflow-server` passes health check at `/health`;
   `bookflow-client` builds with `VITE_API_BASE=https://<server-host>` baked in
   and publishes `client/dist`. The browser calls the API cross-origin; the
   server allows it via CORS (`CLIENT_HOST`).

## 3. Stripe webhook

1. Stripe Dashboard → **Developers → Webhooks → Add endpoint**.
2. Endpoint URL: `https://bookflow-server.onrender.com/api/webhooks/stripe`
3. Events: `checkout.session.completed`, `checkout.session.expired`,
   `payment_intent.payment_failed`.
4. Copy the **Signing secret** (`whsec_...`) → Render → `bookflow-server` →
   Environment → set `STRIPE_WEBHOOK_SECRET` → **Manual Deploy / Save** (restarts).

## 4. Verify

1. Open `https://bookflow-client.onrender.com`.
2. **Sign up** with an email + password (≥ 8 chars), then pick a service →
   **Pay** → Stripe Checkout → test card `4242 4242 4242 4242`.
3. Redirected back to `/checkout/success`; it polls and shows **Payment
   confirmed** once the webhook marks the order paid.
4. Check **Render → bookflow-server → Logs** and **Stripe → Webhooks** for a
   `200` on the delivered event.

## Production checklist

**1. Live Stripe keys**
- Toggle the Stripe Dashboard to **live mode**, grab `sk_live_...`.
- Recreate the webhook endpoint in live mode → new `whsec_...`.
- Update `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET` on `bookflow-server` and
  redeploy. Do a real low-value transaction to confirm, then refund it.
- Keep keys only in Render env vars (never in the repo / client bundle).

**2. Auth** — *implemented*
- Email + password auth ships in `server/src/routes/auth.js`: bcrypt hashes
  (cost 12), JWT bearer tokens (`JWT_SECRET`, 7-day expiry) verified by
  `server/src/middleware/auth.js`. The client stores the token in
  `localStorage` and sends `Authorization: Bearer <token>`.
- Before real launch, add: email verification, rate limiting on
  `/api/auth/*` (e.g. `express-rate-limit`), password reset, and consider
  httpOnly-cookie sessions instead of `localStorage` to reduce XSS token theft.

**3. Paid instance**
- Upgrade `bookflow-server` off `free` — free instances sleep after 15 min
  idle, delaying the first request and slowing Stripe webhook retries.
- On a paid plan, restrict Atlas **Network Access** to Render's static outbound
  IPs instead of `0.0.0.0/0`.
- Add a custom domain + set `CLIENT_URL` explicitly (overrides the derived
  `CLIENT_HOST`) so Stripe redirects and CORS use it.
